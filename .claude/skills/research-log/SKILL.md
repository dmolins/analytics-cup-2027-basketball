# Logging a session

Append to `notes/journal.md`. **Never rewrite or reorder existing entries** — the value
is the chronology, including the dead ends.

Use today's real date and this shape:

```
## YYYY-MM-DD — short title
**Question:** what we were trying to find out
**Did:** what was actually run, with the script or SQL file path
**Found:** the result, with the actual number and the sample size
**Means:** the basketball reading of it, in a coach's language
**Next:** the single next step
```

Rules:
- One entry per session, not one per command.
- **Log failures with the same care as successes.** "We defined a beaten defender as
  >4 ft of separation, it flagged 60% of possessions, so the threshold is wrong" is
  exactly the material the README's methodology section needs, and the Methodology
  criterion rewards transparency about what did not work.
- Always carry the number and the n. A finding without a sample size is not a finding.
- Write **Means** in basketball language, not statistics language. That paragraph is the
  draft of the video script.
- If the entry changes the project direction, also update the shortlist in
  `docs/ideas.md` so the current pick is unambiguous.
